# infra: two-stage lore pipeline — narrative draft → category-discovered canon

**Labels:** infrastructure  
**Status:** Open  

---

## Background

During the session of 2026-04-12, the content pipeline was extended to support
category-level auto-discovery of world lore documents. This surfaced a structural
tension: `narrative/lore/The Roads.md` (type: `narrative`) is generated by the
dedicated `generate_lore_html.py` script with rich cover/audio support, while
`world/lore/` documents (type: `lore`) are discovered and generated by
`generate_all_world_html.py` with `build_myth_html()`.

The two pipelines target the same output slug (`the-roads.html`) but with different
generators. This works today only because `type: narrative` is not in
`PIPELINE_TYPES`, so the batch generator skips it. But it's fragile and the
intended future state was never codified.

The agreed model going forward:

1. **Narrative** = GM draft / bespoke handout. Lives in `narrative/lore/`. Generated
   explicitly via `generate_lore_html.py`. Listed in `_CORE_DOCS` until retired.
   Rich cover (reads `banner:` frontmatter). Audio embedded via `![[file.mp3]]`.

2. **Lore** = canon, category-discovered. Lives in `world/lore/`. Discovered by
   `generate_all_world_html.py`. Appears in `docs/category-lore.html`. Replaced
   the `_CORE_DOCS` entry when the category link suffices.

The transition path for any piece: write and share as narrative → when
canon-ready, copy to `world/lore/`, change `type: lore`, add `visibility:
public` → remove bespoke build step from `netlify.toml` → remove from
`_CORE_DOCS`.

`The Roads` is the first piece undergoing this transition. The lore version
currently doesn't render its cover image because `build_myth_html()` reads
`lk_cover_image:` but the source file uses `banner:` (narrative-generator
convention).

---

## Locked decisions / constraints

- `type: narrative` is not and must not be in `PIPELINE_TYPES`. This is the
  firewall preventing double-generation.
- `generate_lore_html.py` owns the narrative stage. Its CSS and cover logic
  must not be merged into `build_myth_html()` — they serve different purposes.
- In `--public` mode: same visibility rules apply. `visibility: gm_secrets` →
  skipped at all stages.
- `_Generator.run()` interface at the bottom of `generate_all_world_html.py`
  must not change.
- The `netlify.toml` bespoke build steps and `_CORE_DOCS` entries for a piece
  must be removed at the same time it is moved to `world/lore/`. No piece
  should have both active simultaneously.

## Open questions

- **`_CORE_DOCS` retirement timing**: Should The Roads be removed from `_CORE_DOCS`
  immediately on migration, or kept there until the lore category has 2+ items? The
  index looks sparse with only one category-lore link. Suggest: keep in `_CORE_DOCS`
  until a second lore piece is migrated, then retire both at once.

- **Narrative archive**: Should `narrative/lore/The Roads.md` be moved to
  `archive/` or deleted after migration? Suggest: move to `archive/` with a
  note in the frontmatter, rather than delete — it's a useful reference for the
  prose benchmark.

- **Cover image path**: The Roads uses `banner: images/places/798802.jpg` (a local
  vault path). Does `build_myth_html()` + `prepare_image()` handle local paths as
  well as absolute URLs? Needs to be verified during implementation — `_hero_html()`
  does this correctly and is the reference implementation.
